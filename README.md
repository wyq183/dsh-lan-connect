# dsh-lan-connect

局域网连接管理插件（DeepSeek Harness）。

让**手机、平板、另一台电脑**连上同一个 dsh，并且真的用得起来。

---

## v0.2.0 · 桌面端适配（2026-09-27）

本版针对 **DSH Desktop（0.1.7）** 改造，与 v0.1.0（dsh web profile）的差异：

| 变更 | 原因 |
|---|---|
| **删除**「一键让 dsh 本体对外监听」（原 `lib/lan-switch.js` 及其全部接线） | 桌面端刻意只绑 `127.0.0.1`；一旦本体对外，局域网可**绕过门禁**直连，门禁形同虚设 |
| 新增**运行期门禁启停**（`GET\|POST /api/gate/control`） | 顶替原来的「局域网开关」，立即生效、不用重启 |
| `index.js` 加**本体回环断言** | 桌面端天然满足；不满足时大声警告，而不是偷偷改配置 |
| 数据目录**不变**（`~/.dsh/lan-connect`） | 续用既有门禁密码与设备表 |

**桌面端的安全前提因此变成**：本体永远只在回环，局域网**只能**经门禁口进来。

> ⚠️ 门禁开关是**运行期**语义：重启 dsh 后按插件配置恢复（默认开启）。
> 想永久关闭，请改 profile patch 里的 `gateEnabled: false`。

**已验证的链路（实测）**：

- 回环访问门禁口 → 免登录直通（本机方便，`isLocalRequest` 判定）
- 局域网访问门禁口 → 登录页（7138 字节，`title: 需要登录 · dsh`）；未登录 API 返回 401
- 经门禁访问 dsh 受保护路由 → 200（门禁在**服务端**注入 authority-bound cookie）

## 它解决什么问题

dsh 其实早就支持局域网访问了——只要 `webserver` 绑定 `0.0.0.0`，dsh 自己就会：

- 把本机所有局域网 IP 加进 `/api` 的信任名单（防 DNS rebinding）
- 在启动那一行日志里打印带令牌的局域网地址

但只要真去用，会撞上几堵墙：

| 问题 | 现象 |
|---|---|
| **钥匙拿不到** | 访问令牌只在启动日志里出现一次，dsh 一重启就换一把。日志没留就等于没有。 |
| **地址可能是错的** | dsh 只取第一块网卡的地址。开着 VPN / 虚拟网卡时，日志里打的可能是 `26.x.x.x` 那种手机根本连不上的地址。 |
| **二维码＝永久钥匙** | 如果直接把带令牌的地址做成二维码，那张码被拍照/截图就等于永久通行证——直到 dsh 重启。 |
| **看不到、管不了** | 不知道当前有哪些设备连着，也没法让某个设备掉线。 |

这个插件在**已有认证之上**补一个管理面，并针对每一条给出对策：

- 列出所有可用地址，**标出哪个是手机能用的**
- 二维码里放**短时配对码**（默认 2 分钟、刷新即换），不是进程令牌
- 在线设备列表（谁、什么时候、是不是扫码进来的），**重启后仍可见**
- 一键换锁：轮换会话签名密钥 + 撤销配对码

## 安装（桌面端）

本插件装在 `profiles/desktop`：

```
profiles/desktop/node_modules/dsh-lan-connect/     ← 插件本体（从本项目复制 lib/ + ui/ + package.json）
profiles/desktop/cordis.patch.yml                  ← 末尾那段 insert 就是挂载点
```

挂载走 profile 的 **patch 层 insert**（`- insert: - id: lan-connect`）：
不写 `package.json`、不需要 `pnpm install`、不需要联网。

**卸载**：删掉 `cordis.patch.yml` 里那段 insert，再移除 `profiles/desktop/node_modules/dsh-lan-connect`。

### ⚠️ 关于重启（这条踩过坑，务必看完）

- **首次挂载 / 只改 `cordis.patch.yml`**：patch 是热重载的，插件会直接挂上，**通常不用重启**。
- **改了 `lib/*.js` 之后必须重启 dsh**：host 端模块已在内存里，热重载只会**重新应用配置、
  不会重新载入模块**——跑的还是旧代码。

  实测后果：我改了 `lib/index.js` 补上 `start()` 的幂等保护却没重启，于是跑的是旧代码；
  重复调用 `start()` 再次 `listen` 同一端口 → `EADDRINUSE`。
  而 `gateway.js` 是**先赋值 `this.server` 再 listen**，所以失败后
  `gateServer.server` 指向了一个**从未监听的死实例**，原来那个真正在服务的
  server 变成**孤儿**（端口还被它占着、它还在正常服务，但没有任何句柄能关掉它）。

  **危险点：此时界面点「关闭门禁」关的是死实例，真正的门禁仍然开着——UI 会谎报"已关"。**
  只有**重启 app** 能清掉孤儿监听。

  → 教训：`start()` 这类生命期方法必须幂等；并且**改了 host 侧模块，别信"热重载"**。

## 使用

> 📌 **关于本文档里的端口号**
> 下面示例中大量出现的 `3080` 是**旧版 web profile** 的 dsh 端口，属于历史记录，不再逐一改动。
> **桌面端 dsh 的实际端口是 `19387`**（门禁口仍是 `3099`）。
> 插件本身**不写死端口**——它读 `webServer.port`，所以换端口不用改代码。

### 侧边栏浮层（日常用这个）

点侧边栏底部的 **🌐 局域网连接**，直接在页面里弹出浮层：二维码、倒计时、复制按钮。不用另开标签页。

### 完整管理页

`http://127.0.0.1:19387/ext/lan-connect/`（桌面端；端口取 dsh 实际监听的那个），分四块：

- **状态** —— 监听地址、局域网开关、配对码剩余时间
- **连接入口** —— 每个可用地址一张卡，配二维码 + 完整链接 + 复制按钮。私网段（192.168 / 10. / 172.16-31.）排前面并标「推荐」；VPN 之类排后面但仍列出，方便你判断。
- **在线设备** —— 设备类型、IP、最后活动、请求次数；标「扫码」的是通过配对码进来的
- **换锁** —— 轮换签名密钥并撤销配对码

### 配对是怎么走的

```
二维码内容 →  http://192.168.1.13:3080/ext/lan-connect/pair/<短时令牌>
                      ↓ 服务端校验（2 分钟内、未失效）
              303 重定向 →  http://192.168.1.13:3080/?token=<进程令牌>
                      ↓
              浏览器拿到 30 天有效的会话 cookie
```

配对码 32 字节随机、默认 2 分钟、刷新页面即换、换锁即撤销。
**在有效期内可以重复使用**——手机扫码流程经常跨 cookie 上下文（相机预览 → 应用内浏览器 → 系统浏览器），后一个上下文必须能用同一张码走完，否则用户会看到"扫了没反应"。

## 访问门禁（账号密码 + 每周重验）

局域网侧另开一个口（默认 **3099**）：进来先登录，过了才反代到 127.0.0.1 上的 dsh。

```
手机/平板 → http://192.168.1.13:3099/   ← 门禁：登录 + 7 天会话
                   ↓ 已登录才放行
           反代到 http://127.0.0.1:3080/  （附上内部凭据）
本机电脑  → http://127.0.0.1:3080/      ← 直连，不受影响
```

**为什么是独立端口而不是同端口加路径**：页面里的 `/api`、`/plugins/...` 全是绝对路径，
加前缀的话浏览器不会带上前缀，逐个重写既脆弱又容易漏。换个端口之后，手机看到的
origin 就是门禁口，**所有请求天生全部经过门禁**，路径一个字都不用改。
关键性质是：**手机的浏览器自始至终拿不到 dsh 的进程令牌**，它只有自己的门禁 cookie。

- **首次设置**：用**本机**打开 `http://127.0.0.1:3099/`，设账号 + 密码（至少 6 位）。
  局域网设备**不能**抢先设置 —— 否则任何连得上的人都能在你机器上开个账号。
- **有效期**：默认 **7 天**，**绝对过期**：到期必须重输，不因为"一直在用"而续命。
  这正是"每个星期重新验证"的字面含义。想让常用设备少麻烦，调大 `sessionTtlMs` 即可。
- **撤销**：管理页「访问门禁」里可对**单台**设备点撤销，**即时生效**——会话表在我们
  自己手里，删掉即失效。（这点比 dsh 原生的浏览器凭据强：那是进程级签名密钥，热替换不了。）
  也可以一键撤销全部。
- **续期**：同一张表里每台设备有个「续期」按钮，点一下把它的登录再延一周，**不用重新输密码**。
  这是"7 天绝对过期"的**有意例外**——主动点＝明确表达"这台我还在用"。
  它**不是滑动过期**：不点就不会自动续命（若每次访问都自动延期，7 天就形同虚设了）。
  快到期的设备（不足一天）到期时间会**标黄**，提醒你该续了。
- **连续失败限速**：同一 IP 失败 5 次后冷却 60 秒，挡在线爆破。
- **忘记密码**：用本机打开 `http://127.0.0.1:3099/` 直接重设（本机不受门禁约束）；
  或者删掉 `~/.dsh/lan-connect/access.json`。
- **退出**：`POST /__gate/logout`。

### 三种设备分别怎么进

| 设备 | 怎么进 | 要不要密码 |
|---|---|---|
| **本机电脑** | `http://127.0.0.1:3080/` 直连 | 不要（本机免登录，等价于你自己开 dsh） |
| **手机 / 平板** | 扫管理页上的**二维码** | **第一次不要**——码里是一次性配对码（2 分钟有效），扫完直接进 |
| **其他电脑** | 浏览器打开 `http://<本机IP>:3099/` | **要**——输账号密码，之后同一台设备 7 天免再输 |

- `http://<本机IP>:3099/` 里的 IP 就是管理页「连接入口」上标着**推荐**的那个（通常是 `192.168.1.13`）。
  点「复制网址（给电脑）」可以把整条发给别人。
- 那行网址**故意放大了字号**——它是你要手抄到另一台电脑上的东西，小字看不清。
- 还有个「**保存二维码图片**」按钮：把二维码存成 PNG，可以发到别的电脑上再扫，
  不必举着手机对着屏幕。
- **电脑为什么不扫码**：台式机没摄像头，笔记本扫自己屏幕也别扭。所以给电脑留的是最朴素的
  「打开网址 → 输密码」。端口固定是门禁口 **3099**，不是 3080。
- **手机扫码免密只是一次性便利**：配对码 2 分钟作废、刷新即换，而且**只有已经登录的电脑才能看到它**。
  手机上的会话到期后（7 天）照样要回到输账号密码这条路。
- 还没设过账号时**扫码也不放行**——否则谁先扫到谁就进去了。
- 改动本体 bind 之前，二维码指向的是 `3080`；本体只绑回环之后那个地址在局域网里已经不可达，
  所以现在二维码和网址**都指向门禁口 3099**（这个坑是改 host 时引入的，已修）。

## 局域网开关

管理页第一张卡就是开关：**开启 / 关掉局域网访问**。

它改的是 `profiles/<profile>/cordis.patch.yml` 里 `webserver` 那一行的 `host`
（`0.0.0.0` ↔ `127.0.0.1`）。几个要点：

- **要重启 dsh 才生效。** dsh 的 patch watcher 会重放配置，但**没法给一个已经在监听的
  listener 重新绑定地址**——这一点第三方插件 `@linxin666/dsh-remote-web-ui` 的
  `lan-bind.d.ts` 里也写明了。所以页面会如实告诉你"改动待重启生效"，
  而不是假装切成功了。
- **只动一行。** 那个文件里还有 AE MCP、LLM 供应商、一堆注释历史，
  `lib/lan-switch.js` 按 YAML 顶层数组的边界划定 webserver 段，只在段内找 `host` 改一行，
  其余原样保留；改前自动备份，写时用临时文件 + rename 原子替换。
- **找不到那一段就报错**，不会"顺手补一段"——补错了更难查。
- 它同时显示**配置文件里写的值**和**当前实际监听的值**，两者不一致就是"改了还没重启"。

### ⚠ 门禁要生效，dsh 本体必须只绑回环

你的 `webserver` 现在绑的是 `0.0.0.0` —— 也就是说局域网里**任何人都能直接访问
`http://192.168.1.13:3080/` 绕过门禁**。这不是插件的 bug，是配置使然，插件不会替你改。

要让门禁成为唯一入口，把 `profiles/web/cordis.patch.yml` 里那条改成：

```yaml
- id: webserver
  config:
    host: '127.0.0.1'
    port: !!js ctx.webStartup.port ?? 3080
```

然后重启 dsh。在此之前，插件会在启动日志和管理页上持续提示这件事。

## 安全

**除 `/pair/<id>` 外，所有端点都复用 dsh 自己的浏览器会话校验**（`ctx.connection.requestRejection`）：

- 未认证请求一律 401，**入口信息不会吐给未认证的人**
- 会话 cookie 是 `SameSite=Strict` 且按 authority 命名，所以 CSRF 和 DNS rebinding 都拿不到有效认证

`/pair/<id>` 必须免认证——手机第一次进来只持有二维码里那个短时令牌，这正是一次配对该有的样子。它的安全性来自令牌本身。两个细节：

- **防开放重定向**：重定向目标只接受回环或本机枚举得到的局域网地址，绝不照抄请求里的 `Host`（已测 `evil.com` 与 `evil.com@192.168.1.13` 两种花招）
- **不给探测口**：令牌不存在与已过期返回同样的 410

**你必须知道的：**

1. **链接等同这台电脑的钥匙。** 配对码 2 分钟就废，但——一旦手机通过它进了 GUI，那个设备就持有 30 天有效的会话 cookie。
2. **dsh 的 agent 权限是 `danger-full-access`** —— 能连上这个网页，就能在这台电脑上执行任意命令。别在公共 Wi-Fi 开局域网。
3. 「复制链接」在**旧版 host**（尚未重启）下复制的是长期有效的令牌链接，按钮文案会显示为「复制链接（长期有效）」作为提示。

## 已知限制（都是查证过的，不是猜的）

- **「立刻踢掉某一台设备」要分两层看，现在能做一半。**
  - **门禁这一层可以，而且是即时的**：局域网设备的会话表在我们自己手里，
    管理页「访问门禁」里点撤销立刻失效（有测试覆盖，实测通过）。
  - **dsh 原生那一层做不到**：浏览器凭据由进程级签名密钥派生，密钥在内存里不可热替换；
    官方为"配对/撤销"预留的 `api/gate` 事件**至今没有 emit**（我 grep 过源码，只有无关的路径字符串匹配）。
    第三方插件 `@linxin666/dsh-remote-web-ui` 也承认这一点。
  - **实际影响不大**：只要本体老实只绑回环（当前配置就是这样），局域网设备**只能**从门禁进，
    门禁层的撤销就是完整效果。另一个兜底手段是**换锁**（重启后所有 dsh 凭据失效）。
- **反代必须重写「来源类头」。** 这是踩过的坑：`Origin` / `Sec-Fetch-*` 描述的是**外部**的 origin，
  原样转发给回环上游会被 dsh 判成跨站而 **403** —— 症状是 WebSocket 升不上去、GUI 一直
  「自动重连中」、侧边栏「暂无会话」，**看起来像聊天记录丢了**（其实一个字节没丢）。
- **运行时切换 LAN 绑定做不到。** profile patch 的 watcher 无法给运行中的 listener 重新绑定端口，只能写配置文件、下次启动生效。
- **要重启 dsh 才能生效的**：host 端任何 `lib/*.js` 改动、换锁、LAN 绑定变更。
- **在线设备是近似值**：靠 GUI 页面每 20 秒发心跳统计，超过 90 秒无活动视为离线。它反映"浏览器会话"，不是 TCP 连接。

## 与 `@linxin666/dsh-remote-web-ui` 的关系

本机 `.pnpm` 里躺着 `@linxin666/dsh-remote-web-ui@0.3.13`（做同类事的第三方插件，已随整合包卸载）。我读过它的源码，值得记下来的对比：

| 能力 | 它 | 本插件 |
|---|---|---|
| 二维码位置 | 设置按钮旁 | 侧边栏入口 → 页内浮层 |
| 二维码内容 | 短时配对令牌 | 短时配对令牌 |
| 设备会话 | 自己的 device cookie + 持久化表 | 设备表持久化（观测用） |
| **可撤销** | 目标是即时撤销；**实际上对 dsh 原生 `/api` 管不住**（它自己文档里写明了） | 同样管不住，所以只承诺"换锁" |
| 手机适配 | 有竖屏触控适配层 | 无（管理页本身是响应式的） |
| 反向代理 | 有：门禁后把请求反代到 127.0.0.1，手机不接触进程令牌 | 无：配对后仍由 dsh 原生认证接管 |
| LAN 开关 | 写 patch 块，下次启动生效 | 同（一样做不到运行时切换） |
| 防火墙规则 | 会管 Windows / Linux 防火墙入站规则 | 无 |
| 依赖 | 第三方包，兼容性随 dsh 版本漂移 | 零运行时依赖，源码在你手上 |

**它真正比我强的地方**：反代架构（手机永远拿不到进程令牌，理论上撤销更彻底）和手机竖屏适配层。
**它做不到的地方**：因为官方 `api/gate` 从未 emit，它的撤销对 dsh 原生通道同样无效。

想试它，可以单独装（不依赖整合包其余部分），但兼容性要自己验。

## 文件结构

```
dsh-lan-connect/
├── package.json          # 插件清单（dsh.client 声明客户端半侧）
├── install.ps1           # 安装（junction + patch 条目）
├── uninstall.ps1         # 卸载（精确回滚）
├── lib/
│   ├── index.js          # host 端入口：装配 + 挂载路由 + 启动门禁
│   ├── http.js           # 管理路由：认证 / 状态 / 心跳 / 配对 / 换锁 / 门禁会话
│   ├── gateway.js        # 门禁服务器（登录页、会话、代理调度）
│   ├── gate.js           # 账号 + scrypt 密码哈希 + 7 天会话表（持久化、可续期）
│   ├── proxy.js          # 反向代理到 127.0.0.1 + 内部凭据兑换
│   ├── lan-switch.js     # 局域网开关：精确改写 patch 里 webserver 的 host
│   ├── pairing.js        # 配对令牌状态机（TTL、刷新即失效）
│   ├── devices.js        # 设备追踪 + 持久化（原子写、防抖）
│   ├── qr.js             # 零依赖二维码编码器（byte mode, EC L/M, 版本 1-40）
│   └── client.js         # 客户端半侧：侧边栏入口 + 浮层 + 心跳
├── ui/
│   ├── index.html        # 管理页（原生 JS，无构建）
│   └── login.html        # 登录 / 首次设置页
└── scratch/              # 开发期验证脚本（非交付物）
```

运行时数据在 `~/.dsh/lan-connect/`：`devices.json`（设备表）、`access.json`（账号 + 会话）。
目录刻意不叫 `dsh-lan-connect`——插件源码就在那个路径下，同名会把数据文件写进源码目录。

**零运行时依赖** —— 只用 Node 内置模块和 dsh 通过 cordis 上下文提供的服务。

`test-lan-switch.mjs` 里最关键的一条断言是「**除 host 一行外内容完全一致**」——
那份 `cordis.patch.yml` 里混着注释、多个顶层元素和 insert 块，改坏任何一处都很难查，
所以测试直接拿全文逐字符比对。它还覆盖了 CRLF 换行不被破坏、引号风格保留、
重复写同值不产生多余改动、找不到 webserver 段时**报错而不是乱写**。

`test-gate.mjs` 覆盖：未设账号时的分支、局域网不能抢先设账号、未登录被拦（页面与 /api）、
本机回环免登录、错误账号/密码提示一致、正确登录种 HttpOnly+SameSite=Strict cookie、
带会话放行、**内部凭据确实让上游认账**、伪造 cookie 被拒、**撤销即时生效**、会话过期、
退出登录、连续失败触发限速。

`test-http.mjs` 覆盖：认证拦截、状态结构、心跳归并、二维码、换锁、404、回环降级、
配对令牌全流程（签发/使用/重放/刷新失效/过期/防开放重定向/轮询不续期）、门禁端点与绕过告警。
